# characters/

Role-based character packs: data that maps semantic roles (idle, listen,
talk, work, work_talk, celebrate, question, neutral_hold) onto concrete
actions and clips, with per-role fallbacks so a sparse pack still drives every
transition. Schema: `protocol/character-pack.schema.json` (v2). Full contract:
`docs/characters.md`.

- `cappi-original/pack.json` — clean-checkout **default**. The canonical
  schema-v2 conversion of the original v1 Cappi manifest (98x98 GIFs,
  filenames/actions/modes preserved; `question`/`work_talk` state-owned).
  Apache-2.0, owner-approved (see `cappi-original/provenance.json` for
  per-file sha256; root `LICENSE` governs). Asset mirror:
  `watch-app/.../assets/characters/cappi-original/`.
- `dot-default/pack.json` — original hand-authored CC0 vectors (96x96), full
  roles except `work_talk` (exercises the standing-speech fallback in
  production). Kept to demonstrate pack extensibility (alternate dimensions,
  sparse roles, no scheduler edits).
- `ember-min/pack.json` — sparse original CC0 example (64x64, alternate
  dimensions). No `celebrate` or `work_talk` roles: both fall back safely.
- `registry.json` — published single source of character capabilities for the
  bridge/plugin (generated by `CharacterRegistry.toBridgeJson`; legacy
  `/watch/cappi` action ids remain as an adapter, the role contract is
  preferred). Do not hand-edit: regenerate from the packs.
- `example-pack/pack.json` — valid schema-v2 authoring example (sparse:
  no `celebrate`/`work_talk`, both fall back safely). Copy this shape to
  author a new pack: no scheduler edits and no resource registration are
  needed (packs resolve via `discoverPackIds` + asset paths). Not shipped in
  the app asset mirror and not in `registry.json`, which is generated from
  the canonical shipped packs (`cappi-original`, `dot-default`, `ember-min`)
  only.

The original Cappi GIFs ship in this tree under `cappi-original/`
(rights cleared, Apache-2.0, owner-approved). The pre-clearance private
staging copies under `.release-work/local-assets/cappi/` are preserved
outside the tree for reference; a saved pre-clearance `cappi-legacy-local`
selection migrates to `cappi-original` at sanitize time.
